# Charter 010: GNOME Shell extension (T015)

Session: 2026-10-24, about 30 minutes. Tester: builder (charter track, wave 6). Code under test: `dev` at 6308b65. Since then `dev` declares Shell 48 to 50 and adds `make ext-pack` (PR #79); nothing here depends on that change.

## Mission

*Explore* the extension's client, controller and menu model, and the installer, *with* daemon restarts while connected, pause from the CLI, event bursts, hostile socket servers and odd previews *to discover* stale or wrong state, leaks and unsafe rendering.

**Out of reach here:** a real GNOME Shell. The panel widgets, Looking Glass leak checks and light/dark panels can't run in the tools container. The owner has already passed the Shell 48.7 manual matrix (`docs/release.md`, "Manual check log"). This session drives `controller.js` and `menu.js` under plain gjs against the **real** daemon, plus a hostile fake server. That is closer to production than the fixture tests' fake server, but it says nothing about St/Clutter behaviour.

## Setup

- gjs in the tools image, importing `/src/extension/{controller,menu}.js` (read-only mount) from a probe script in the scratchpad.
- The real daemon on a private Xvfb with temp XDG dirs, and `xclip` copies with synthetic text.
- The state timeline is sampled every 50 ms: icon name, status line, first entry labels.
- Installer: `rstory install-gnome-extension` with a temp `XDG_DATA_HOME` and a fake `gnome-extensions` script on `PATH`.

## What I tried

1. **Daemon interplay:**
   - copies, including `C:\new\temp` and a text containing U+202E (RLO);
   - `pause --for 90s` and `resume` from the CLI;
   - daemon SIGTERM and restart, SIGKILL and quick restart;
   - 300 copies in a burst;
   - `clear --yes`.
2. **Hostile server.** The daemon is stopped, and a Python server on the socket path accepts and sends 64 MiB without a newline. The probe watches the gjs RSS.
3. **Installer:**
   - install, then check modes;
   - `--enable` with an `enable` that fails;
   - an older `version-name` on disk (upgrade message);
   - the user's dev symlink at the target, a dangling symlink, a regular file at the target;
   - a read-only extensions dir;
   - a non-GNOME session;
   - uninstall twice;
   - `--enable` with a `gnome-extensions` that hangs;
   - doctor with a hanging `gnome-extensions`.

## Observations

- **CLI pause.** Shown within about 1 s: icon `paused`, status `Paused — resumes in 1:30`, ticking. Resume flips it back.
- **Daemon restarts.** Daemon stop: icon `disconnected` and the menu reduces to its placeholder. Restart: back to full state in 2.4 s (with a 200 ms backoff in the probe; production starts at 1 s and caps at 30 s). SIGKILL plus a quick restart recovered in about 0.2 s.
- **300-copy burst.** The state changed about 20 times a second for 2 s, coalesced by `#refresh`'s `again` flag. In the Shell, every change runs `menu.removeAll()` and a rebuild, even while the menu is open.
- **Previews.**
  - `C:\new\temp` is labelled `C:⏎ew\temp`. The daemon's preview escapes `\n` as backslash-n but leaves literal backslashes alone, and `entryLabel` turns every backslash-n into ⏎.
  - The RLO character reaches the label unescaped (`synthetic-‮txt.exe` renders reversed as `synthetic-exe.txt`).
- **Hostile server.** The 64 MiB line is buffered whole: gjs RSS went from 98 MB to 229 MB, then dropped after the server closed. `read_line_async` has no length cap.
- **Requests.** A request has no timeout. While the daemon is wedged (charter 002, X1), `#refresh` stays in flight and the menu stays stale with no feedback.
- **Installer.**
  - Files are 0644.
  - The upgrade message names the version.
  - A dev symlink at the target is replaced by a real directory, and the linked checkout is untouched.
  - A read-only dir fails with `Permission denied (os error 13)`, exit 1.
  - A regular file at the target fails with `Not a directory (os error 20)`, exit 1, and no path in either message.
  - A dangling symlink: `--uninstall` says `Nothing to remove.` and leaves the link.
  - Not GNOME: warns and installs.
  - `--enable` with a hanging `gnome-extensions` never returns (killed at 10 s). Doctor caps the same program at about 300 ms.
  - A failed enable prints the re-login hint twice (once from install, once from enable).

## Findings (by severity)

### E1 Low: backslash-n in content is shown as a line break

**Repro:** copy `C:\new\temp`. The menu shows `C:⏎ew\temp`.

The root cause is shared with the CLI and picker: `Preview::from_bytes` (`src/domain/entry.rs`) does not escape `\`, so the preview is ambiguous.

**Failing assertion to add**, in `src/domain/entry.rs` tests:
`assert_eq!(Preview::from_bytes(b"C:\\new").as_str(), "C:\\\\new");`
Then in `menu.test.js`: `assertEquals(entryLabel('C:\\\\new', false), 'C:\\new')` (the JS undoes `\\` before `\n`).

Escaping `\` changes the preview contract in `/contracts/protocol.md`, so that part is a product question.

### E2 Low: bidi and line-separator characters pass through previews

**Repro:** copy text containing U+202E. The menu, `rstory ls` and the picker render the rest reversed.

`is_control()` covers only Cc. U+202A to U+202E, U+2066 to U+2069 and U+2028/U+2029 are not escaped.

**Assertion to add:**
`assert!(!Preview::from_bytes("a\u{202e}b".as_bytes()).as_str().contains('\u{202e}'));`

### E3 Low: the client buffers unbounded lines

A process of the same user that binds the socket while the daemon is down can grow gnome-shell's memory without bound (+130 MB for a 64 MiB line). Suggestion: cap a line at 2 MiB + 1 KiB like the daemon, then drop the connection.

### E4 Low: no request timeout

A wedged daemon leaves the menu stale and gives no feedback on actions. A timeout of about 5 s per request that rejects with `timeout` would let the controller show "daemon not responding".

### E5 Low: installer rough edges

- `--enable` waits forever on a hung `gnome-extensions`.
- Errors don't name the path.
- A dangling symlink is left by `--uninstall`.

Assertions to add in `tests/install_gnome.rs`:
- a fake `gnome-extensions` that sleeps 30 s makes `execute(.., enable)` return within 2 s;
- with a dangling symlink at the target, `--uninstall` removes it.

### E6 Info

- The menu rebuilds about 20 times a second during bursts. It needs a check in a real Shell that an open menu stays usable (charter step "daemon restart while the menu is open").
- Reconnect after a long outage can take up to 30 s (the backoff cap).

## Open questions

- Should the protocol preview escape `\` (E1)? It's a contract change.
- The leak check and the open-menu restart behaviour remain manual (Shell 48.7 done by the owner; 49 and 50 per `docs/release.md`).
