# Charter 005: privacy filters (T017)

Session: 2026-10-24, about 30 minutes. Tester: builder (charter track, wave 6). Code under test: `dev` at 6308b65.

## Mission

*Explore* the privacy filters *with* hinted copies (exact, odd casing, hint-only, stalled hint), size boundaries, the pause gate (mid-burst, across restarts, on a full disk) and trace-level log scanning for planted canaries *to discover* any path where sensitive or paused content is recorded or logged.

## Setup

- The real binary with temp XDG dirs on a private Xvfb, on headless sway and with the tray on a private `dbus-launch` bus.
- Hinted offers come from the support clients (`tests/support/x11.rs`, `wl_client.rs`) in an ad-hoc probe test in a scratch copy of the repo.
- Canary `zzcanaryQ7` and other synthetic text only.

## What I tried

1. **Hints on X11 and Wayland:**
   - `x-kde-passwordManagerHint` plus text;
   - odd casing (`X-KDE-PasswordManagerHint`, `X-KDE-PASSWORDMANAGERHINT`);
   - a hint value other than `secret`;
   - hint only, with no text;
   - a hint type whose value is never written (stalled).
2. **Size boundaries.** Exactly 1 MiB and 1 MiB + 1 on X11 (single property and INCR) and on Wayland.
3. **Pause gate mid-burst.** Five rounds of 60 xclip copies 12 ms apart, with `rstory pause` issued after 250 to 450 ms. A copy started after the pause was acknowledged must never be recorded.
4. **Pause and restarts.**
   - A timed pause ending in-process.
   - An indefinite pause and resume.
   - A restart while paused.
   - A restart after a timed pause ended while the daemon was down.
5. **Pause on a full disk** (charter 001 setup).
6. **Log scan.** `RUST_LOG=trace`, X11 plus a private D-Bus with the tray. Steps:
   - copy the canary as plain, multi-line and 160 kB;
   - `show`, `show --json`, `copy`, `pin`/`unpin`, `rm`;
   - `show`/`copy` with the canary as the ref, a raw socket request with the canary in `ref`, in `op` and in an unknown arg;
   - `GetLayout` on the tray's dbusmenu;
   - pause, copy the canary, resume.
   Then grep the whole log. The same scan ran on sway at trace.

## Observations

- **Hints.** An exact hint is skipped on X11 and on Wayland (`skipped_sensitive` +1). Hint-only and stalled-hint offers are skipped too. Any hint value is skipped, which is conservative. Odd casing is recorded, as spec 005 documents.
- **Size.** 1 MiB is recorded; 1 MiB + 1 is dropped whole (`skipped_oversize`) on every path, never truncated.
- **Mid-burst.** Across all five rounds, 0 copies started after the pause acknowledgement were recorded. Every copy started before it was recorded (20/24/28/32/36), and `skipped_paused` counted the rest.
- **Pause in-process.** A timed pause ending, a resume, and a restart while still paused never record a copy made during the pause.
- **Pause across downtime.** A timed pause that ended while the daemon was down does leak: the start-up read records the selection copied during the pause (P1).
- **Full disk.** `rstory pause` fails with `internal` (exit 1), and the daemon keeps recording (P2).
- **Logs.** 241 trace lines (X11, zbus, mio, tokio) and 164 on sway: 0 canary hits. Error messages echo only the ref the user typed (`No entry zzcanaryQ7`), never content.
- **Tray.** The tray's dbusmenu `GetLayout` returns entry previews, including the canary, to any client on the session bus. That is the tray's purpose, but it is a second channel besides the uid-checked socket.

## Findings (by severity)

### P1 Medium: a copy made during a timed pause is recorded when the pause expires while the daemon is down

**Repro:**
1. `rstory pause --for 1s`.
2. `printf synthetic-held-2 | xclip -selection clipboard -i -loops 1 &`
3. `kill -TERM <daemon>`, then `sleep 1.2`.
4. Start the daemon. `rstory ls` shows `synthetic-held-2` at index 0.

This is the same defect as charter 004, D2. The realistic trigger is a systemd `Restart=` or an upgrade while a password manager still owns the clipboard. The failing assertion is in charter 004, D2.

### P2 Low: the pause gate fails open when the store can't persist

**Repro:**
1. Fill the store's filesystem.
2. `rstory pause` prints `internal error (see the daemon log, c2)` and exits 1.
3. `rstory status --json` shows `{"state":"recording"}`.

The user sees an error, but if space is freed later the daemon records again without the user retrying. Suggestion: close the gate in memory first, persist best-effort, and return success with a warning.

**Assertion to add** (FaultFs ENOSPC on `commit`, `tests/daemon_pause.rs` style): `assert_eq!(status["state"], "paused")` after the `pause` request, whatever its reply.

### P3 Info

- The tray exposes previews to every session-bus client. Worth one line in the README's privacy notes.
- Odd-casing hints are recorded, as documented.
